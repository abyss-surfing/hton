Статус: задача реализации; завершение не заявлено. Точный синтаксис:
[CLI](../../../CLI.md); владельцы файлов: [карта](../../../sdd/map/README.md).
Область: [CLI SDD](../../../specs/sdd-cli.md),
[installer SDD](../../../specs/sdd-installer.md),
[lifecycle SDD](../../../specs/sdd-lifecycle.md),

[runtime SDD](../../../specs/sdd-runtime-safety.md).

`bin/hton` остаётся тонким Bash-диспетчером из любой cwd, `scripts/*` — самостоятельные
Unix-way команды, общий shell-код — `lib/`. Сложные правила конфигурации,
жизненного цикла, журналирования и применения принадлежат единственному Core,
а не копируются в shell. Rust helpers собираются вне слабого VPS. В R1 нет
обязательного controller, API daemon или веб-админки.

## Установка

- OS-диспетчер читает os-release. Ubuntu/Debian используют соответствующие ОС
  официальные Docker repository/codename; неподдержанная ОС получает инструкции
  и повторную проверку. Получение зависимостей — явный bootstrap, не часть up.
- На чистой Ubuntu install получает базовые пакеты, Docker/Compose и закреплённые
  готовые артефакты. Повторный запуск сохраняет выполненные шаги и ручные правки.
- Источник настроек — hton.yaml и отдельные versioned config/modules/*.yaml.
  Не исполнять YAML или .env как shell. Legacy .env в R1 объясняется для ручного
  переноса; автоматическая миграция принадлежит будущему configurator.
- Install profile — подсказка первого запуска, а не перезапись сохранённого состава.
  `--menu` пересматривает сохранённый выбор. Core предоставляет предложения через
  trusted catalogue; shell показывает их и возвращает точные ID, не дублируя список
  модулей и не редактируя YAML. Modules add получает ресурсы и создаёт только недостающие конфиги, сохраняя новый
  модуль disabled/incomplete; enable выполняется отдельно после проверки готовности.
- Проверить домен/DNS либо дать инструкцию получения бесплатного домена с актуальным
  примером. Без домена установка может закончиться unpublished/degraded с применимым
  предупреждением о блокировке; это не подтверждённая публичная HTTPS-готовность.
- Явно подтверждать изменения чужих ресурсов, привилегий и публичного 443.
  `--yes` не заменяет эти согласия, dry-run не пишет и не загружает ресурсы.

### Выбор состава и порты VPN

Install selection является отдельным изменением desired state. Выбор Amnezia сам по
себе не ассоциирует найденный контейнер: требуется exact ID, свежая qualification
по fingerprint и отдельное согласие на journalled adoption. Adoption даёт только
lifecycle scope; remap требует отдельного snapshot и согласия.

После qualification и явной association Core планирует для каждого выбранного
managed VPN service уникальный случайный host-порт 5000–6000 включительно. Одна
служба с TCP и UDP использует одно число. Кандидат проверяется по свежим host/Docker
reservations и сохраняется CAS в существующих settings этого сервиса. Повторный
`scripts/install` использует сохранённый selection и порт без новой случайности; смена
binding не выводится из discovery и не происходит автоматически. HAProxy сохраняет
публичный TCP/443, а Outline не перенастраивается без отдельного выбора и согласия.

## Хранение и запуск

Вся платформа размещается под /opt/hton: защищённый дистрибутив отдельно от
config/ и Git-ignored work/. Secrets — config/secrets, рабочие реестры/журналы/
данные/bundles — work/, временные сокеты — /run/hton. Настраиваемые логи по
умолчанию /var/logs/hton, с обязательным редактированием секретов, ротацией и удалением записей старше недели.
Изменяемые Docker-входы сохраняются; принятые артефакты immutable и используют
host bind mounts. Runtime не читает живые изменяемые YAML при accepted boot.

Устанавливаются отдельные data/guardian/ACME service/timer units; PATH shim —
опционально с исходным ответом «нет». Старт принятого bundle независим от Core
и сети доставки образов. Whole-server down сначала сохраняет stopped intent/epoch,
запрещает автозапуск и автоматические задания, затем останавливает всех связанных
членов с индивидуальными результатами. Частичный результат не выдаётся за успех.
Восстановление выполняется переустановкой из приватного `.secrets` и последующим явным `up`; отдельного restore-режима в R1 нет.

Маршрутизация R1: HAProxy L4/SNI → Caddy TLS/обычный сайт и выбранные Xray endpoints;
TCP и UDP не смешиваются. D80 разрешает native Amnezia REALITY passthrough;
настоящий доменный сертификат относится к обычному HTTPS-сайту. Конкретная
интеграция требует exact installed identity/SNI/target/restart evidence. Не менять стороннюю систему
на основании обнаруженного контейнера без явной association/approval.

## Завершение

I3-A связывает CLI с завершёнными Core/runtime операциями; I3-B доставляет
Compose/systemd/build bindings. Зависимости: I0–I2; интеграция — I4.
Затем U0 и F0 проверяют usage/exit matrix, zero-write dry-run, interrupted setup,
повторные up/down, reboot со stopped intent, malformed YAML и безопасное удаление.
Дополнительные нагрузочные/deployment-проверки определяются после этих результатов.
Docker staging кандидата опционален; нативная валидация остаётся обязательной.
