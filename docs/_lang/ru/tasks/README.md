# Задачи реализации

Актуализировано 2026-11-07: учтены OR-52 (публикация гостевых артефактов и URL в приватном `.secrets`), OR-53 (ротация логов с забыванием старше недели) и OR-54 (приватный `.secrets` — единственная долговременная копия, отдельного backup/restore нет).
Общий план: [ROADMAP](../../../ROADMAP.md); порядок и владение пакетами:
[IMPLEMENTATION-ORCHESTRATOR](../../../IMPLEMENTATION-ORCHESTRATOR.md); фактический
прогресс: [IMPLEMENTATION-STATUS](../../../IMPLEMENTATION-STATUS.md).

Приоритет имеют [требования владельца](../../../OWNER-REQUIREMENTS.md), затем
согласованные [спецификации](../../../specs/README.md),
[общие интерфейсы](../../../INTERFACES.md) и [карта файлов](../../../sdd/map/README.md).
[00-decisions.md](00-decisions.md) сохранён как исторический журнал: прежние
.env-driven меню, обязательная веб-админка/controller, ранние тестовые шлюзы,
старые пути var/* и IPv6 не определяют текущую реализацию R1.

R1 включает самодостаточный Bash CLI/Core, декларативные конфиги модулей,
реестр установленного состава и возобновляемую настройку, независимый runtime,
IPv4 HAProxy/Caddy с обычным сайтом, Xray, собственные сертификаты, установку,
журналы с недельной ротацией; восстановление — переустановка из приватного `.secrets` (отдельного backup/restore нет). Уже установленная Amnezia остаётся обязательной
частью R1. Владелец D80 принял штатный REALITY passthrough с настоящим
сертификатом обычного сайта; exact installed identity/SNI/target/restart semantics
требуют подтверждения до реализации конкретной интеграции. Дополнительный certificate manager для неё не разрешён.
API/configurator/web/accounts, IPv6 и клиентский uplink в R1 не реализуются;
контракты будущего API сохраняются без зависимости CLI от API daemon.

| Задача | Текущий владелец семантики |
|---|---|
| [t02](t02-cli-compose.md) | CLI, установка и системные entry points: I3-A/I3-B |
| [t07](t07-certs.md) | Собственные сертификаты и безопасная доставка: I2-C/I3-B |
| Остальной R1 | Пакеты I0–I4 оркестратора и G0–G6 ROADMAP |

Сначала завершается весь выбранный scope I0–I4, затем выполняются юнит-тесты U0,
после них функциональные F0. Дальнейшая приёмка A0 определяется по результатам.
Нативные валидаторы остаются обязательным поведением продукта; изолированная
Docker-проверка кандидата опциональна. Контракты и сборка не доказывают готовность.
Публичное переключение 443 и изменение чужих ресурсов требуют отдельного
конкретного согласия; начало реализации не разрешает deployment на внешнем VPS.

Уточнение D81 (2026-11-01): продолжать более крупными связанными пакетами и
параллельными исполнителями при доступности. Промежуточные сборки отложены до
полной готовности выбранных планов; затем сборка → U0 → F0. До этого разрешена
сверка исходников/синтаксиса/документов без запуска продукта и компиляции.
